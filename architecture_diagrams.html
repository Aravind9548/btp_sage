Architecture Diagrams

Saga Compensation Coordination Benchmark — System design, election flow, and cloud mapping

1. System Architecture Overview

Figure 1: Three-layer architecture. Services run as Python classes (mapping to Lambda). Infrastructure provides state management (mapping to DynamoDB/SNS/SQS). Three coordination strategies use the same infrastructure.

2. Path D: Election & Compensation Flow

Figure 2: Path D's election + graph-aware dispatch. Candidates race for a lease; exactly one wins. The winner reads the dependency graph and dispatches independent compensations in parallel. Notification starts only after Payment finishes (dependency edge).

3. Crash Recovery via Lease TTL

Figure 3: Crash recovery flow. orch-1 crashes after compensating Payment. Its lease expires (no renewal). orch-2 re-acquires, reads DynamoDB to see what's already done, and completes the remaining compensations. No step runs twice.

4. Cloud Deployment Architecture

Figure 4: Side-by-side architecture. Left: pure-Python benchmark (controlled experiment). Right: LocalStack cloud layer (same coordination logic, cloud-backed infrastructure). The drop-in replacement pattern proves the architecture maps directly to AWS.
