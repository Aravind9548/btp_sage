03The Four Sweepsclick any figure to enlarge
Figure 01makespan vs. width
The headline result. A climbs in a straight line because it never overlaps anything; B and D stay flat because both compensate in parallel. D tracks B with a constant gap rather than a widening one.
Figure 02correctness rate
Correctness rate. Choreography fails the ordering check on every single run — not occasionally, 0% across the board. Everything else is perfect. This is the chart that makes the tradeoff concrete.
Figure 03ablation
Ablation — my favourite chart here. Same election mechanism, only the dispatch order swapped. LIFO stays correct but comes out 194% slower at width 8. So the election is not what makes Path D fast; the graph-aware scheduler is.
Figure 04correctness premium
What correctness costs. Path D's overhead against choreography as width grows. It stays near 13% instead of widening — a bounded premium, which is the part that makes it defensible in practice.
Figure 05cluster size 4–16
Does the election become the bottleneck? Scaling from 4 to 16 services, all racing for the same lease. It does not — contention is exactly one conditional write per service, and the loser learns immediately.
Figure 06concurrency degradation
Overlapping sagas. Ratio of makespan under load to makespan in isolation. Hovers near 1.0, so concurrent sagas do not interfere — each elects its own leader on its own lease key.
